# Primitive DB

Консольное приложение, имитирующее работу с простой базой данных.
Позволяет создавать и удалять таблицы, а также добавлять, читать, изменять
и удалять записи в них. Данные хранятся в JSON-файлах.

## Установка

Для разработки:

```bash
uv sync
```

или через `make`:

```bash
make install
```

Установка как консольной команды:

```bash
uv build
uv tool install dist/primitive_db-0.5.0-py3-none-any.whl
```

или через `make`:

```bash
make build
make package-install
```

## Запуск

После установки:

```bash
database
```

Из папки проекта без установки:

```bash
uv run database
```

или через `make`:

```bash
make run
```

## Проверка кода

```bash
make lint
```

Команда запускает линтер `ruff` (`uv run ruff check .`).

## Структура проекта

| Модуль | Назначение |
|---|---|
| `src/primitive_db/main.py` | точка входа в приложение |
| `src/primitive_db/engine.py` | основной цикл, обработка ввода, вызов команд |
| `src/primitive_db/core.py` | бизнес-логика: таблицы и CRUD-операции |
| `src/primitive_db/parser.py` | разбор команд: `values`, `where`, `set` |
| `src/primitive_db/utils.py` | загрузка и сохранение метаданных и данных таблиц |
| `src/primitive_db/decorators.py` | декораторы и замыкание для кэширования |
| `src/primitive_db/constants.py` | константы |

## Хранение данных

| Файл | Что хранит |
|---|---|
| `db_meta.json` | описание таблиц: имена, столбцы и их типы |
| `data/<имя_таблицы>.json` | записи таблицы, например `data/users.json` |

Файлы создаются в текущей папке, поэтому программу нужно запускать
из одной и той же папки.

## Управление таблицами

### Команды

| Команда | Описание |
|---|---|
| `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` | создать таблицу |
| `list_tables` | показать список всех таблиц |
| `drop_table <имя_таблицы>` | удалить таблицу вместе со всеми её записями (с подтверждением) |
| `help` | справочная информация |
| `exit` | выход из программы |

Поддерживаемые типы данных: `int`, `str`, `bool`.

Столбец `ID:int` добавляется в начало таблицы автоматически.

### Пример использования

```
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.
>>>Введите команду: list_tables
- users
>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.
>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
Таблица "users" успешно удалена.
```

При ошибке в команде программа сообщает о ней и снова ждёт ввода:

```
>>>Введите команду: create_table orders price:float
Некорректное значение: price:float. Попробуйте снова.
>>>Введите команду: hello
Функции hello нет. Попробуйте снова.
```

## CRUD-операции

### Команды

| Команда | Описание |
|---|---|
| `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` | добавить запись |
| `select from <имя_таблицы>` | показать все записи |
| `select from <имя_таблицы> where <столбец> = <значение>` | показать записи по условию |
| `update <имя_таблицы> set <столбец> = <значение> where <столбец> = <значение>` | изменить записи |
| `delete from <имя_таблицы> where <столбец> = <значение>` | удалить записи (с подтверждением) |
| `info <имя_таблицы>` | показать столбцы таблицы и количество записей |

### Правила записи значений

- строки — в кавычках: `"Sergei"` или `'Sergei'`;
- целые числа — без кавычек: `28`;
- логические значения — `true` или `false`;
- в `insert` значение `ID` не указывается, оно генерируется автоматически;
- все поля обязательные: в `insert` передаются значения для всех столбцов,
  кроме `ID`, в том порядке, в котором столбцы были созданы;
- в `set` можно изменить несколько столбцов через запятую:
  `set age = 29, is_active = false`;
- столбец `ID` изменить нельзя;
- условие `where` — одно сравнение на равенство.

### Пример использования

```
>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".
Функция insert выполнилась за 0.000 секунд
>>>Введите команду: insert into users values ("Anna", 31, false)
Запись с ID=2 успешно добавлена в таблицу "users".
Функция insert выполнилась за 0.000 секунд
>>>Введите команду: select from users
Функция select выполнилась за 0.000 секунд
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
| 2  |  Anna  |  31 |   False   |
+----+--------+-----+-----------+
>>>Введите команду: select from users where age = 28
Функция select выполнилась за 0.000 секунд
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+
>>>Введите команду: update users set age = 29 where name = "Sergei"
Функция select выполнилась за 0.000 секунд
Запись с ID=1 в таблице "users" успешно обновлена.
>>>Введите команду: delete from users where ID = 1
Функция select выполнилась за 0.000 секунд
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".
>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 1
```

Примеры ошибок:

```
>>>Введите команду: insert into users values (Anna, 25, true)
Некорректное значение: Anna. Попробуйте снова.
>>>Введите команду: insert into users values ("Anna", 25)
Ошибка: Ожидалось значений: 3, получено: 2.
>>>Введите команду: select from users where age = "25"
Некорректное значение: '25'. Попробуйте снова.
>>>Введите команду: update users set ID = 10 where name = "Anna"
Ошибка: Столбец ID нельзя изменить.
```

## Дополнительные возможности

Повторяющаяся логика вынесена в декораторы и замыкание `create_cacher`
(`src/primitive_db/decorators.py`).

### Обработка ошибок

Декоратор `@handle_db_errors` перехватывает ошибки операций с базой данных
(`KeyError`, `ValueError`, `FileNotFoundError` и другие) и выводит понятное
сообщение. Программа не завершается из-за ошибки, а снова ждёт команду.

### Подтверждение опасных действий

Декоратор `@confirm_action` запрашивает подтверждение перед удалением таблицы
и удалением записей. Операция выполняется только при ответе `y`, любой другой
ответ её отменяет:

```
>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
Операция отменена.
```

### Время выполнения

Декоратор `@log_time` выводит время выполнения операций `insert` и `select`:

```
Функция select выполнилась за 0.000 секунд
```

### Кэширование запросов

Результаты одинаковых запросов `select` сохраняются в кэше: повторный запрос
не читает файл и не выполняет поиск заново, поэтому строки о времени
выполнения у него нет. Кэш сбрасывается после любой команды, которая меняет
таблицы или данные (`create_table`, `drop_table`, `insert`, `update`, `delete`).

```
>>>Введите команду: select from users
Функция select выполнилась за 0.000 секунд
+----+------+-----+-----------+
| ID | name | age | is_active |
+----+------+-----+-----------+
| 2  | Anna |  31 |   False   |
+----+------+-----+-----------+
>>>Введите команду: select from users
+----+------+-----+-----------+
| ID | name | age | is_active |
+----+------+-----+-----------+
| 2  | Anna |  31 |   False   |
+----+------+-----+-----------+
```
